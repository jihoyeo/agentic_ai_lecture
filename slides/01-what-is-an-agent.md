## "LLM"과 "에이전트(Agent)"는<br>무엇이 다른가?

<br>

ChatGPT에 질문하는 것과, 에이전트가 일을 *처리*하는 것의 차이를
이해하는 것이 이 워크샵 전체의 출발점입니다.

---

# 먼저, LLM을 빠르게 복습

**LLM (Large Language Model)** = 다음에 올 단어(토큰)를 확률적으로 예측하는 모델

```
입력:  "한국의 수도는"
        ▼  (다음 토큰을 예측)
출력:  "서울" (확률 98%) ... "부산" (1%) ...
```

- **프롬프트(prompt)** 를 받아 **텍스트**를 생성한다 — 그게 전부다.
- 방대한 텍스트로 학습 → 놀라운 언어·추론 능력.
- 하지만 본질은 "**그럴듯한 다음 텍스트 생성기**".

> 이 본질 때문에 생기는 **3가지 한계**를 보겠습니다.

---

# LLM의 한계 ① — 환각 (Hallucination)

모르는 것도 **그럴듯하게 지어낸다.**

```
Q: "2026년 5월 21일 서울의 날씨는?"
A: "맑고 기온은 23도입니다."   ← 실제로는 알 수 없는 정보
```

- LLM은 "모른다"고 말하기보다 **그럴듯한 답**을 만들도록 학습됨.
- 정답인지 *스스로 검증할 방법이 없다.*

> 사실 확인이 필요한 일에 LLM 단독은 위험하다.

---

# LLM의 한계 ② — 멈춰 있는 지식

학습이 끝난 시점 이후의 일은 **알지 못한다.**

```
Q: "지금 몇 시야?"
Q: "오늘 환율은?"
Q: "이 CSV 파일에서 통행량이 가장 큰 구간은?"
A: ... LLM은 답할 수 없다.
```

- 학습 데이터는 특정 시점에 **고정**되어 있다 (knowledge cutoff).
- **실시간 정보**, **내 데이터**, **방금 일어난 일** → 접근 불가.

---

# LLM의 한계 ③ — 행동을 할 수 없다

LLM은 **텍스트만 생성**한다. 세상에 무언가를 *하지* 못한다.

- 계산기를 두드릴 수 없다 (큰 수 곱셈도 자주 틀림)
- 데이터베이스를 조회할 수 없다
- 시뮬레이션을 실행할 수 없다
- 이메일을 보낼 수 없다

```
"택시 50대로 시뮬레이션 돌려서 평균 대기시간 알려줘"
        ▼
LLM 혼자서는 — 시뮬레이션을 돌릴 수 없다.
```

> ①②③ 한계를 **메우는 것**이 바로 "에이전트"입니다.

---

# 그래서, "Agentic" 이란?

에이전트 = LLM에게 **눈·손·기억·자율성**을 붙인 것.

| LLM 단독 | Agentic AI |
|---|---|
| 텍스트만 생성 | **도구**로 행동한다 |
| 한 번 답하고 끝 | **반복**하며 목표를 추적 |
| 정해진 입출력 | **스스로 다음 단계를 결정** |

> 핵심 4요소: **자율성 · 도구 사용 · 목표 지향 · 반복 루프**

---

# Workflow ↔ Agent 스펙트럼

"에이전트"는 0과 1이 아니라 **정도(degree)**의 문제다.

```
 단순/예측가능 ◀───────────────────────────────▶ 자율적
   LLM 호출 → 프롬프트 체이닝 → 라우팅 → 도구 사용 → 에이전트

  └──── Workflow ────┘          └──────── Agent ────────┘
   경로를 *사람이* 코드로 고정     경로를 *LLM이* 스스로 결정
```

- **Workflow**: 단계가 미리 정해진 파이프라인. 예측 가능·안정적.
- **Agent**: LLM이 무슨 도구를 언제 쓸지 직접 정한다. 유연·강력.

> 실무 팁: 가능하면 단순하게. *진짜 필요할 때만* 에이전트로.

---

# 에이전트의 해부학 — 5가지 구성요소

```
       에이전트  =  LLM  +  네 가지 부품

   🧠  Model          어떤 LLM을 쓰는가
   📜  Instructions   시스템 프롬프트 · 역할 부여
   🔧  Tools          호출 가능한 함수들
   💾  Memory         대화와 관찰의 누적
   🔁  Loop           멈출 때까지 추론·행동을 반복
```

이 워크샵의 지도입니다:
S1 = `Model`·`Instructions` · S2 = `Tools` · S3 = `Memory`·`Loop`

---

# 에이전트 루프 — 한눈에

```
   목표(Goal):  "자족도가 가장 낮은 생활권은?"
       │
       ▼
   추론(Reason)  →  행동(Act)  →  관찰(Observe)
     ▲                                   │
     └────────  답이 부족하면 반복  ────────┘
       │  (충분하면 종료)
       ▼
   최종 답변
```

- **추론** — 지금 무엇이 필요한가? · **행동** — 도구를 호출 · **관찰** — 결과 확인
- 답이 충분할 때까지 **반복** → 이 루프를 S3에서 **직접 코딩**합니다.

# 사례 ① — mega-region-ai 에이전트

사용자가 한국어 한 문장을 입력하면:

```
사용자: "경기 남부 생활권의 자족도는 어때?"
   │
   ├── 추론: "자족도 분석 도구가 필요하다"
   ├── 행동: analyze_self_containment() 호출
   ├── 관찰: { 내부통행: ..., 유출: ... }
   │
   └── 답변: "경기 남부 생활권은 자족도 68%로,
             생활권으로서 독립성을 보이나
             서울 의존이 여전히 큽니다."
```

> 13개의 도구 + 반복 루프 — S2~S3에서 우리가 비슷하게 만듭니다.

# 사례 ② — DTUMOS 에이전트

자연어 요청을 시뮬레이션 실행으로:

```
사용자: "대전에서 택시 50대로 시뮬레이션 돌려줘"
   │
   ├── 추론: 요청에서 파라미터 추출
   │         (도시=대전, 차량=50, 모드=택시)
   ├── 행동: run_simulation(city="daejeon", fleet=50)
   ├── 관찰: { 평균대기: 4.2분, 서비스율: 91% }
   │
   └── 답변: "대전 택시 50대 기준 평균 대기시간은
             4.2분, 서비스율은 91%입니다."
```

> 같은 패턴 — `목표 → 추론 → 행동 → 관찰 → 답변`.
