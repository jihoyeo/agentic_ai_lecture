# 바이브 코딩이란?

> 코드를 한 줄씩 치지 않음.
> 하고 싶은 걸 **말로 설명하면**, AI 코딩 에이전트가 대신 만들어 줌.

- 대표 도구 — **Codex**, Claude Code, Cursor, Copilot
- 그럼 사람이 할 일은? → **"무엇을 만들지 정하고, 잘 설명하기."**

<br>

> 그래서 실력 차이는 — **얼마나 잘 설명하느냐**에서 갈림.

---

# 오늘 만들 것 — 지도 + 채팅 웹앱

```
   [ 왼쪽 · 약 65% ]                [ 오른쪽 · 약 35% ]
   ───────────────────────         ───────────────────────
     지도 (deck.gl)                  채팅창 (AI 도우미)

     · 도시 = 점                     "서울 → 인천 통근량?"
     · 통근 흐름 = 곡선               → "520명입니다"
   ───────────────────────         ───────────────────────
```

- 왼쪽 — **지도.** 수도권 18개 도시의 통근 흐름을 그림.
- 오른쪽 — **채팅창.** 데이터를 물어보면 답해 줌.
- 이 둘이 한 화면에 나란히.

---

# 완성품이 아니라, 빌드 스펙

`labs/lab0_vibe_coding/` 를 열면 — **완성된 앱이 없음.** 딱 두 개뿐임:

```
  BUILD_SPEC.md    만들 앱을 아주 자세히 적은 "빌드 스펙"
  data/            지도에 쓸 데이터 (도시 18 · 흐름 48)
```

- 완성품을 주면? → 구경에 그침. **직접 만들어 봐야** 머리에 남음.
- 그래서 앱은 **여러분이** 만듦 — `BUILD_SPEC.md` 를 코딩 에이전트에 넘겨서.

> 오늘의 진짜 교재는 `BUILD_SPEC.md`. 이게 **얼마나 자세한지** 꼭 볼 것.

---

# 잘 만들려면, 잘 설명해야 함

막연하게 부탁하면? → **막연한 게 나옴.**

```
  ❌  "통근 지도 앱 만들어줘"

  ⭕  자세한 빌드 스펙:
      - 어떤 데이터를 쓰는지 (필드·샘플까지)
      - 무슨 기능을 (지도엔 무엇, 채팅은 무엇)
      - AI는 어떤 역할인지 (예시 대화까지)
      - 어떤 기술로 (React · deck.gl · VWorld …)
```

> AI에게 건네는 이 '요청서' — 그게 **빌드 스펙(build spec)** 임.

---

# `BUILD_SPEC.md` 에는 뭐가 들어갈까

좋은 스펙엔 네 가지가 꼭 들어감. 오늘 쓸 예제 스펙도 이대로 짜여 있음.

| 항목 | 무엇을 적나 |
|---|---|
| **데이터 설명** | 어떤 파일에 어떤 필드가 있는지, 샘플까지 |
| **구현 기능** | 지도엔 무엇을, 채팅은 무엇을 하는지 |
| **AI Agent 역할** | 무엇을 답하고 계산은 어떻게 — *예시 대화* 까지 |
| **프론트엔드 요구사항** | React · deck.gl · VWorld 베이스맵까지 *구체적으로* |

> 나중에 직접 만들 때도 — 이 네 가지를 이만큼 자세히 적을 것.

---

# 데이터 — 수도권 통근

실제 연구 프로젝트 `mega-region-ai` 에서, 제일 단순한 데이터를 그대로 가져옴.

```
  cities.json   서울·인천·수원·성남 … 수도권 18개 도시 (이름·좌표)
  flows.json    도시 → 도시 통근 흐름 48개 (출발·도착·통행량)
```

- 작고 직관적임 — 지도에 점·곡선으로 바로 그려짐.
- 채팅 AI도 딱 이 데이터만 보고 답함.

---

# AI Agent 의 역할

채팅창 AI가 할 일은 하나 — **"수도권 통근 데이터 안내 도우미".**

```
  데이터에 그대로 있는 걸 물으면   →  찾아서 바로 답
   "서울→인천 통근량?"               "520명입니다"

  계산이 필요한 걸 물으면         →  직접 계산해서 답
   "서울로 들어오는 총 통근량?"      도착지가 서울인 흐름을 모두 합산
```

- 모르는 건 안 지어냄 — 데이터로 답하거나, "모른다"고 하거나.
- 역할·동작·예시 대화를 또렷이 적을수록 → 결과가 좋아짐.

# AI 코딩 에이전트와 일하는 법

- **한 번에 하나씩** — 스펙을 통째로 던지지 말 것. 6단계를 하나씩.
- **계획부터** — "코딩하기 전에, 어떻게 만들지 먼저 말해줘."
- **단계마다 실행** — 한 단계 끝나면 직접 돌려 보고 넘어감.
- **피드백은 구체적으로** — "이상해요" ❌ / "A를 물으니 B가 나옴, C가 맞음" ⭕
- **막히면 그대로** — 오류 메시지를 통째로 붙여넣고 "이거 왜 이래?"
