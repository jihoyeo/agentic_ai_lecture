# 워크샵 회고 — 우리가 걸어온 길

```
 S1   에이전트 해부학      LLM의 한계 → Model·Instructions
       │
 S2   도구 (Tools)        function calling 한 바퀴
       │
 S3   루프 (Loop)·기억     추론→행동→관찰 반복, 메모리
       │
 S4   확장                멀티에이전트·RAG·MCP·평가·안전
       │
 S5   캡스톤              ← 지금 여기
```

# 프로젝트 아이디어 카탈로그

**난이도 ★ — 새 도구 추가**
- `compare_regions` — 두 시군구의 통행 지표를 나란히 비교

- 요금·속도 파라미터를 바꿔 가며 비교하는 도구

**난이도 ★★★ — 에이전트 구조 확장**
- 새 서브에이전트 추가 (예: 리포트 작성 전담)

# 평가 기준

| 항목 | 본다 |
|---|---|
| **작동** | 에이전트가 끝까지 돌고 답을 내는가 |
| **도구 설계** | 스키마가 명확한가, 결과가 간결한가 |
| **루프 이해** | 멀티스텝·종료 조건·에러 처리가 들어갔는가 |
| **평가** | Mock/Scripted LLM 테스트가 하나라도 있는가 |
| **발표** | 무엇을, 왜 그렇게 만들었는지 설명되는가 |

> 화려함보다 — **개념을 제대로 썼는가**.

---

# 발표 가이드 (1팀 5분)

1. **무엇을 만들었나** — 한 문장 + 데모 질문 1개
2. **어떻게 동작하나** — 도구 / 루프 / (있다면) 서브에이전트
3. **막혔던 점** — 어떤 한계를 만나 어떻게 풀었나
4. **라이브 시연** — 에이전트에게 질문 → 추론·도구 호출 과정 보여주기

> 코드가 완벽하지 않아도 좋습니다. **이해**를 보여 주세요.
