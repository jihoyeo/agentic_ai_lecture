# Lab 0 — 바이브 코딩으로 에이전트 만들기

> **이 랩은 워크샵의 출발점입니다. `lab1`~`lab5` 보다 *먼저* 합니다.**
> 원리를 몰라도 괜찮습니다 — 먼저 직접 *만들어* 보고, "이게 왜 이렇게 동작하지?"
> 라는 궁금증을 안고 `lab1`~`lab5` 로 넘어갑니다.

---

## 1. 이 랩에서 하는 일

이 폴더에는 **완성된 앱이 없습니다.** 대신 이것만 있습니다:

```
labs/lab0_vibe_coding/
├── README.md       ← 지금 보는 파일 (랩 안내)
├── BUILD_SPEC.md    ★ 만들 앱을 매우 상세히 적어 둔 "빌드 스펙"
└── data/
    ├── cities.json  수도권 18개 도시
    └── flows.json   도시 간 통근 흐름 48개
```

여러분이 할 일: **`BUILD_SPEC.md` 를 AI 코딩 에이전트(Codex 등)에게 주고,
바이브 코딩으로 직접 앱을 구현**하는 것입니다.

만들 앱은 — **왼쪽에 지도, 오른쪽에 채팅창**이 있는 한 페이지 웹 앱입니다.
지도에는 수도권 통근 흐름이 그려지고, 채팅창에서 데이터를 물어보면 답해 줍니다.

## 2. 왜 앱을 미리 안 만들어 주나요?

> 바이브 코딩은 **직접 해봐야** 늡니다.

- 완성품을 주면 "구경" 만 하게 됩니다. 직접 만들면 *체득* 합니다.
- 이 랩의 진짜 교재는 **`BUILD_SPEC.md`** 입니다. 그게 *얼마나 상세한지* 를
  보세요 — 좋은 결과물은 그만큼 구체적인 스펙에서 나옵니다.
- 여러분도 앞으로 자기 서비스를 만들 때 이렇게 스펙을 쓰면 됩니다.

```
  Lab 0   바이브 코딩으로 "일단 만들기"   ← 지금 여기
    │
  Lab 1~5  그 안에서 무슨 일이 일어나는지 "원리 이해하기"
    │
  캡스톤   원리를 알고 다시 제대로 만들기
```

## 4. 진행 순서

### 단계 1 — `BUILD_SPEC.md` 정독
무엇을 만드는지, 데이터·기능·AI 역할·프론트엔드 요구사항이 어떻게 적혀 있는지
꼼꼼히 읽습니다. **이 상세함의 수준** 을 눈에 익히세요.

### 단계 2 — API 키 발급
Gemini 키와 VWorld 키를 발급받아 둡니다 (`BUILD_SPEC.md` §5 참고).

### 단계 3 — 코딩 에이전트로 단계적 빌드
`BUILD_SPEC.md` 의 **§6 단계적 빌드 계획** 을 그대로 따릅니다.
스펙 전체를 한 번에 던지지 말고, **1단계 → 실행 → 2단계 → 실행 …** 으로 진행하세요.
(보내는 법은 `BUILD_SPEC.md` 의 부록에 있습니다.)

### 단계 4 — 예시 대화로 검증
`BUILD_SPEC.md` §4-4 의 예시 대화 6개를 직접 입력해, 기대대로 답하는지 확인합니다.
틀리면 *구체적으로* 피드백해 고칩니다.

### 단계 5 — `lab1` 로
완성하면, 코딩 에이전트가 만든 코드를 열어 보세요. 그 안에 들어 있는
**시스템 프롬프트 · LLM 호출 · 데이터 처리** 가 바로 `lab1`~`lab5` 의 주제입니다.

## 5. 이 랩의 핵심 교훈

> **막연하게 요청하면 막연한 결과가, 상세하게 요청하면 쓸 만한 결과가 나온다.**

`BUILD_SPEC.md` 를 다시 보세요. 이 스펙이 명시한 것들:
- **데이터 설명** — 어떤 파일에 어떤 필드가 있는지, 샘플까지
- **구현 기능** — 지도에 무엇을, 채팅이 무엇을 하는지
- **AI Agent의 역할** — 무엇을 답하고, 계산은 어떻게 하는지, 예시 대화까지
- **프론트엔드 요구사항** — React, deck.gl, VWorld 베이스맵처럼 *구체적인* 기술 지정

여러분이 자기 아이디어를 만들 때도 이 항목들을 이만큼 구체적으로 적으면 됩니다.

## 6. AI 코딩 에이전트와 일하는 법

- **한 번에 하나씩** — 6단계를 한 번에 ❌ → 한 단계씩 요청하고 실행 ⭕
- **계획을 먼저 물어라** — "코딩 전에 어떻게 만들지 순서를 말해줘"
- **구체적으로 피드백** — "이상해요" ❌ → "A를 물었더니 B가 나왔는데 C가 맞아요" ⭕
- **막히면 그대로 물어라** — 오류 메시지를 통째로 붙여넣고 "이거 왜 그래?"

## 7. 흔한 함정

- 스펙을 안 읽고 바로 "만들어줘" → 막연한 결과. §1 부터 읽으세요.
- 6단계를 한 번에 요청 → 어디서 틀렸는지 못 찾습니다. 쪼개세요.
- 단계마다 실행 안 함 → 오류가 쌓입니다. 매 단계 실행하세요.
- 키를 코드에 직접 적음 → 위험합니다. 반드시 `.env` 에 두세요.
