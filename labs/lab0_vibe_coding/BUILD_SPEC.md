## 0. 한 줄 소개

수도권 18개 도시의 **통근 흐름을 지도에 시각화**하고, 옆 **채팅 에이전트**가 데이터에
대한 질문에 답하는 한 페이지 웹 앱.

## 2. 데이터

`data/` 폴더의 JSON 두 개. (`mega-region-ai` 의 수도권 예제.)

| 파일 | 형태 | 예시 |
|---|---|---|
| `cities.json` (18개) | `{id, name, name_ko, lat, lon}` | `{"id":"SEO","name":"Seoul","name_ko":"서울","lat":37.5665,"lon":126.9780}` |
| `flows.json` (48개) | `{origin, dest, count}` | `{"origin":"SEO","dest":"INC","count":520}` |

`flows.origin/dest` 는 `cities.id` 를 참조합니다. **흐름은 방향이 있습니다** —
`SEO→INC` 와 `INC→SEO` 는 서로 다른 항목.

## 3. 지도

- **React + Vite** + **deck.gl** (`<DeckGL>`).
- **베이스맵 — VWorld**: `TileLayer` 로 깔기.
  `https://api.vworld.kr/req/wmts/1.0.0/{KEY}/Base/{z}/{y}/{x}.png` · 키는 `.env` 의 `VITE_VWORLD_KEY`.
- **도시** — `ScatterplotLayer`. 점 크기 ∝ 그 도시의 총 통근량(inflow+outflow). 호버 툴팁(한글 이름 + 총량).
- **흐름** — `ArcLayer`. 곡선 굵기 ∝ `count`.
- 초기 뷰: 경도 127.0, 위도 37.4, 줌 8~9.

## 4. AI Agent

채팅의 AI 는 **"수도권 통근 데이터 안내 도우미"** 다. cities/flows 두 데이터에 대한
질문에 답하는 것이 유일한 임무다.

### 4-1. 핵심 원칙

- **모르는 건 모른다고 한다** — 데이터에 없는 건 지어내지 않는다.
- **계산은 코드가, 말은 LLM 이** — 데이터 조회·합계·최댓값은 *반드시 도구를 호출*해 얻은 값을 인용한다. 머릿속으로 계산하지 않는다.
- 답은 한국어, 2~4문장, 친근한 말투. 숫자를 답할 때는 어떻게 얻은 값인지 한 줄로 함께 밝힌다.

### 4-2. 능력 ↔ 도구

LLM 은 데이터를 직접 보지 않는다. 대신 아래 **5개 도구**를 호출해서 데이터를 다룬다.
각 행이 곧 구현 단위다 — 능력 하나에 도구 하나.

| # | 능력 | 도구 | 입력 | 반환 |
|---|---|---|---|---|
| 1 | 도시 찾기 | `find_city(query)` | `query: string` (한글/영문/id 부분 일치) | `[{id, name_ko, lat, lon}, …]` |
| 2 | 두 도시 사이 단방향 통근량 | `get_flow(origin, dest)` | id 또는 한글이름 | `{origin, dest, count}` |
| 3 | 두 도시 사이 왕복 통근량 | `get_round_trip(city_a, city_b)` | id 또는 한글이름 | `{a_to_b, b_to_a, total}` |
| 4 | 한 도시의 inflow / outflow / total | `get_city_totals(city)` | id 또는 한글이름 | `{city, inflow, outflow, total}` |
| 5 | 통근량 상위 N 개 흐름 | `get_top_flows(n)` | `n: integer = 5` | `[{origin, dest, count}, …]` |

> 도구는 모두 **순수 JS 함수** 다. 입력을 받아 결과를 돌려준다 — 그게 전부다.
> LLM 은 이 함수들의 **이름·설명·파라미터(JSON 스키마)** 만 본다 (코드는 못 본다).

### 4-3. 에이전트 루프

LLM 호출은 한 번으로 끝나지 않을 수 있다. 다음 루프를 돌린다:

```
1. 사용자 질문을 contents 에 넣는다
2. LLM 에 (contents, tools) 를 보낸다
3. 응답이
   - text 면        → 그 텍스트가 최종 답. 끝.
   - functionCall 이면 → 우리가 그 함수를 실행하고, 결과를 contents 에 functionResponse 로 붙여 다시 LLM 호출 (2로 돌아감)
4. 안전망: max_steps = 6. 넘으면 tools 없이 한 번 더 호출해 최선의 텍스트를 받는다.
```

이렇게 만들면 "가장 많은 구간 찾고, 그 두 도시 사이 왕복도" 같은 **멀티스텝** 질문도 풀린다.

### 4-4. 검증 대화 — 아래처럼 동작해야 한다

| 사용자 | 부르는 도구 | 기대 답 |
|---|---|---|
| 서울에서 인천으로 가는 통근량은? | `get_flow(서울, 인천)` | 520 |
| 데이터에 어떤 도시들이 있어? | `find_city("")` 또는 전체 안내 | 18개 한글 이름 나열 |
| 용인은 어디쯤이야? | `find_city(용인)` | 위도 37.2411, 경도 127.177 |
| 서울로 들어오는 통근량 총합은? | `get_city_totals(서울)` | 4,040 (inflow) |
| 통근량이 가장 많은 구간은? | `get_top_flows(1)` | 서울→성남, 540 |
| 수원과 용인 사이 왕복 통근량은? | `get_round_trip(수원, 용인)` | 510 (260+250) |
| 가장 많은 구간을 찾고, 그 두 도시 왕복도 알려줘 | `get_top_flows(1)` → `get_round_trip(...)` | 서울↔성남, 540+520=1,060 ← **멀티스텝** |

### 4-5. (선택) 답에 등장한 도시는 지도에서 잠시 강조한다

LLM 답변 텍스트에 들어 있는 도시 이름을 추출해 `ScatterplotLayer` 에서 일시적으로
강조(테두리/크기 변화). 이건 채팅 UI 의 책임이지 에이전트 도구는 아니다.

## 5. 기술 스택 / 키 보안

- **React + Vite**, **deck.gl**, 베이스맵 **VWorld**.
- **LLM**: Google Gemini, 모델 `gemini-2.5-flash`. 무료 키 <https://aistudio.google.com/apikey>.
- **Function calling**: Gemini REST 의 `tools.functionDeclarations` 사용.
  요청 본문 모양:
  ```json
  {
    "systemInstruction": { "parts": [{ "text": "<역할/원칙>" }] },
    "contents":          [ ... ],
    "tools":             [{ "functionDeclarations": [<도구 스키마 5개>] }],
    "generationConfig":  { "temperature": 0.2 }
  }
  ```
- **키 보안**: `GEMINI_API_KEY` 는 `.env` 에만. **브라우저에 절대 노출 금지** —
  Vite 개발 서버의 미들웨어 프록시(`/api/chat`)가 키를 붙여 대신 Gemini 호출.

## 6. 단계적 빌드

한 번에 다 만들지 않는다. 각 단계 끝나면 직접 실행해 보고 다음으로.

1. Vite + React 프로젝트 → `data/` 의 두 JSON 콘솔 출력.
2. deck.gl + VWorld 베이스맵 띄우기.
3. 도시 `ScatterplotLayer` + 흐름 `ArcLayer` 그리기.
4. 채팅 패널 UI (말풍선 + 입력창, 아직 LLM 없음).
5. **도구 5개** 를 순수 JS 함수로 작성 (`src/lib/tools.js`). 콘솔에서 직접 호출해 검증.
6. **Vite 프록시 + Gemini 연결** — 도구 스키마 동봉해서 `/api/chat` 으로 호출.
7. **에이전트 루프** 구현 (`src/lib/agent.js`) — §4-3 의사코드 그대로.
8. §4-4 검증 대화 7개를 모두 통과시킨다. 멀티스텝 마지막 줄 포함.

## 7. 안 만드는 것

로그인·DB·업로드·모바일 전용 화면·다중 페이지·사용자 저장. 위 8단계가 끝나면 완성.
